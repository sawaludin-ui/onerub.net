# Release and recovery gates

A release has separate states: source implemented, local tests passed, browser acceptance passed, real dependency integration passed, contract deployed, source verified, environment synchronized, web deployed, production acceptance passed. Do not collapse them into one checked item.

## Pre-release

1. `npm ci` and `npm ls tmp --all` must agree with the0.2.7 override/lock. `npm audit` reports known dependency advisories only, not application safety.
2. `node --test --test-concurrency=1 tests/*.test.mjs`; no mainnet funds. Legacy compiler snapshots and V2 compiler target must stay distinct.
3. `node scripts/release-check.mjs`; inspect final git diff and added files. No .env/.local/DPAPI/recovery material in Git or Vercel uploads.
4. Production web build, browser desktop/mobile role+cost above fold, keyboard focus cycles/restore, reduced motion, observer and namespaced task routing. Simulated task screenshots remain labeled synthetic.
5. Credential ACL allowlist and verified encrypted backups. Preserve AUTH/encryption; generate independent decision MAC and initial receipt signer only with guarded explicit operation. Old material stays in encrypted archive, not new all-keys plaintext replicas.
6. Exact deployment gas/config preflight, budget bounded, pending transaction journal checked before retry. No automatic duplicate deployment.
7. Deploy once only after review; confirm chain56 receipt, address, registry,token,fee,signer,minReview,minParticipants,protocolRevision,runtime hash. Never alter immutable V1.
8. Submit exact deployed compiler input to source verifier, read exact creation/runtime match, bind to deployment tx/block/address, record activation manifest. BscScan verification is a separate explicit organizer requirement.
9. Upsert allowlisted service environment encrypted; participant wallet keys, backup key/material and deployer key never go to web runtime. Rebuild because browser/server import the same static active deployment.
10. Deploy web, verify exact production domain and public config/address/ABI/health; new funding stays disabled if active deployment is legacy V1. Do not claim dependency readiness from flags.

## Recovery

- Preserve the current Windows profile/machine for CurrentUser DPAPI; it is not an offline disaster recovery substitute.
- Backup key file is outside encrypted recovery material. Test decrypt+integrity and snapshot restore in random isolated namespace; never replace production records.
- Record original ACL/byte backup and validate exact originals before migration. Encryption/auth drift is a hard stop; no silent key replacement.
- Decision MAC rotation preserves key IDs and bounded verification windows through active task expiry. Retired key failure does not replace an existing verdict.
- Evaluator signer rotation changes only new V2 tasks; old exact signer keys may be retained in a controlled keyring. Permanent revocation makes affected unsettled tasks refundable, not migratable or guaranteed paid.
- Runbook must distinguish payment confirmed, winning artifact available, retrieved, integrity verified and recovery required.

## External completion gates

Real participant mainnet E2E and30eligible addresses cannot be generated by automated test fixtures. Record only genuine use. Official project form needs participant Binance login; no credentials/session/pairing codes should be collected by ONERUB. No submission or accepted eligibility without organizer proof. No recurring task or backup schedule is created by this runbook.
